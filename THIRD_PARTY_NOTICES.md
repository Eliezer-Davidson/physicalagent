### Evidence captures that are referenced but not included

Some documents cite raw capture directories — `artifacts/hw/…` (hundreds of MB per
run), `artifacts/live/…` and `artifacts/session3/…`. Those are **offline captures
and are not part of this repository**; the numbers taken from them are quoted, with
their source directory named, in the write-ups under `docs/evidence/`.

### HiWonder robot software

The ROSPug, TonyPi and MiniHexa run **Shenzhen HiWonder Technology's** own
onboard stacks — `ros_robot_controller`, the TonyPi `ActionGroups` database,
`pug_app`, `AGC.runActionGroup` and the BLE/serial firmware. **None of that
source is vendored in this repository.** `robot_nodes/physicalagent_deadman.py`
imports `ros_robot_controller.msg`, which exists on the robot, not here.
`docs/hardware_notes.md` and `docs/alternatives.md` record *facts and
measurements* about those stacks, observed and extracted by the author; no
vendor table or datasheet is reproduced verbatim.

### Vendor CAD, drawings and datasheets

HiWonder STEP/DWG/IGES/DXF files, Waveshare and FEETECH STEP files, and all
vendor PDF datasheets are **not present in this repository** and are not
redistributed. They left this tree on 2026-08-02 and `*.pdf` is in
`.gitignore`. Obtain them from the respective vendors' own download pages.

Note that HiWonder's CAD being publicly downloadable is not, by itself, a
licence to produce and sell derivative printed parts. That question is open and
this repository does not answer it in either direction.

## 4. A note on `tools/sonic_timescale.c`

This file was written for this repository: an `LD_PRELOAD` shim that rescales the simulation clock.
Its design was derived by disassembling a shipped vendor static library to
confirm one `timerfd` flag value — a legitimate interoperability observation,
recorded in the file's own comments. No vendor code is reproduced. The compiled
object is not distributed (`tools/*.so` is git-ignored); only the source ships.
