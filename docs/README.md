# docs — what is in here

Start with **[`EVIDENCE.md`](EVIDENCE.md)**: every claim in the front-page README
and the file in this repository that carries it, ending with the claims this
repository deliberately does *not* make.

| Path | What it is |
|---|---|
| [`EVIDENCE.md`](EVIDENCE.md) | The claim-by-claim evidence index. Read this one. |
| [`evidence/`](evidence) | Dated write-ups of the runs themselves — two G1 hardware sessions, the ER-2 tool-call transcript, the ROSPug field run, the get-up figure. |
| [`design/`](design) | The design documents that are engineering assets: the original design spec, the fleet design, the G1 control architecture, the G1 safety-tier table, and the HiWonder dead ends. |
| [`hardware_notes.md`](hardware_notes.md) | The long one (≈800 lines): everything measured on the HiWonder robots — topics, services, servo domains, deadman timing, networking. A reference, not a narrative. |
| [`alternatives.md`](alternatives.md) | Every option that was considered and parked, with the reason. |
| [`tool_surface_design.md`](tool_surface_design.md) | How the model-facing tool surface is shaped and why it refuses rather than guesses. |
| [`rospug_ros_graph.txt`](rospug_ros_graph.txt) | Raw introspection dump off the quadruped: 105 topics, 158 services, 26 nodes. |
| [`operations/`](operations) | Session-time material: the demo runbook and the day-2 hardware plan. Dated, kept because they show how the sessions were actually run. |
| [`media/`](media) | The figures the README uses. |
